Stripe built an internal AI assistant with over 1,000 skills, 500 internal tools, and 83% of the company using it every week. They did that by managing context correctly. Stripe wanted every employee to have an assistant connected to their data warehouse, Slack, and internal tools. But load 1,000 skills and 500 tools into one system prompt, and the agent runs out of room before it even starts the task. So they built it on DeepAgents, our open source agent harness. Each skill carries its own list of allowed tools, so picking a skill decides which tools load, and the agent's context ends up with just a handful, not all 500 available tools at once. Of course, a handful of foundational skills always stay pinned no matter what. So Stripe's core context and policies never get dropped by accident. So that covers what stays in context. Now the agent runs and writes code outside a sandbox, but for safety, it calls into the sandbox to run that code. So execution stays isolated without ever exposing Stripe's real infrastructure or credentials. The agent also needs to remember things across a session, so a virtual file system backed by S3 lets it persist state instead of rereading everything from scratch on every turn. One Stripe engineer built the first working version of CHI in a single week because DeepAgents had already solved the hard infrastructure problems. Adoption grew 16-fold in about a month, and CHI now runs over 60,000 sessions a week. As the engineering manager for Stripe's agent foundation team put it, the DeepAgents layer solves all the non-Stripey problems, so his team could focus on Stripe's problems instead.
